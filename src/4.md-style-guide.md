# Markdown 文件格式指南

定義撰寫技術文件時應遵循的 Markdown 格式規範。核心原則是：在使用文字編輯器閱讀原始檔時，也要清楚明確。


## 基本排版

 - 標提使用 `#` 構成, 不使用分隔線
 - 標題與內文間至少一個空白行
 - 段落結束前 (新標題開始前) 至少兩個空白行
 - 列表由一個空白開始.
 - 不使用表格排版，若有類似需求，採用替代方案。
 - 避免使用 emoji ，減少使用強調 ( **像這樣** ) 的樣式。
 - 參照到檔名、變數、模組名、參數名等程式性的單詞時，使用反引號，例如 `4.md-style-guide.md` 這樣的寫法。
 - **括號用半形優先**，外側留一個空白：`文字 (內容) 文字`。半形括號緊貼漢字會擠在一起，
   外側的空白就是它的呼吸空間。逗號、句號、頓號、冒號等其餘標點**維持全形** ——
   中文行文裡它們的斷句節奏比半形清楚，而頓號根本沒有半形對應。


範例格式：

    # 主標題

    內容開始，標題下方有一個空白行。

     - 列表符號前保持一個空白
     - 多個項目時均同

    段落結束內容。


    ## 新段落

    新段落內容，前方有兩個空白行。


## Code Block 規範

 - Markdown 中的 code block 使用四個空白的縮排表現
 - Code block 前後至少都要有一個空白行
 - 只在明確被要求時使用三個反引號格式

範例：

    前面的內容。接下來這段程式使用四格空白縮排表示：

        const example = {
          root: element,
          enabled: true
        };

    後面的內容。


避免使用三個反引號, 除非明確指示; 一般情況下無論語言, 都使用四格縮排.

    // 當明確要求使用時才採用三個反引號
    function complexFunction() {
      return 'highlighted code';
    }
