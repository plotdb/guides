# Version Control 慣例


## CHANGELOG.md

每次實作完，請先將變更依 feature / bug fix / tweak 分類整理至 `CHANGELOG.md`。

格式以 `## v(semver)` 分隔各版本，最新尚未進版的變更放在最前面的 `## master` section：

    ## master

     - upgrade dependencies


    ## v0.0.2

     - features:
       - add anchor editing feature
     - tweaks:
       - require holding space to drag viewport
     - bug fix:
       - fix typo in variable name


    ## v0.0.1

     - init release


## Commit

被要求 commit 時：

 1. `git diff` 確認目前尚未送交的變更範圍
 2. 摘要整理後更新 `CHANGELOG.md` 的 `## master` section
 3. `git add` 相關檔案後 commit

### 縮寫：a.c.p

用戶輸入 `a.c.p` ( 或 `ok a.c.p`、`acp` ) 時，代表 **add + commit + push**，
即依上述 Commit 流程做完後再 `git push`：

    git add <相關檔案> && git commit -m "..." && git push

同理 `a.c` 表示只做 add + commit，不 push。


## Tag / Release

被要求 tag 時：

 1. 查閱最後一次 tag ( 見下方「Tag 命名」，前綴會影響排序，要指定查哪一側 )
 2. 依本次修改決定 major / minor / patch 升版：
    - patch：bug fix、小 tweak
    - minor：新 feature、較大幅度改動
    - major：破壞性變更、架構重寫
 3. 將 `CHANGELOG.md` 的 `## master` section 改為該版本號 ( 如 `## v0.1.0` )
 4. 選擇以下其中一種方式建立 release：


### Tag 命名：`src/` 與 `dist/` 前綴

一個 repo 若把建置產物放進 git ( 有 release branch )，同一個版本就同時存在於兩個
地方：release branch 上的產物，以及產生它的 source commit。fedep 1.8.0 起
`publish -g` 會兩邊都打 tag，並用前綴標明指向哪一側：

 - `dist/vX.Y.Z` 指向 release branch 上的建置產物，GitHub release 也指向這裡。
   要安裝、要相依時用這個
 - `src/vX.Y.Z` 指向產生該版本的 source commit。要閱讀、diff、bisect、
   checkout 原始碼時用這個

安裝時照常帶 tag，斜線不影響 npm 解析：

    npm install github:owner/repo#dist/v1.2.3

兩側都加前綴，而不是只加新的那一個。若只把 source 標成 `src/`、release 維持裸名，
同一個 repo 裡就會出現 `v1.2.3` 是產物、`v1.2.4` 是原始碼，而名字本身分不出來。

沒有前綴的 `vX.Y.Z` 有兩種可能，判準是這個 repo 有沒有 release branch：

 - 有 release branch：該 tag 是 fedep 1.8.0 以前留下的，指向建置產物。舊 tag
   一律不動 —— 改名會讓已發布的 release 連結、以及既有的安裝失效
 - 沒有 release branch：這個 repo 只有一側，沒有東西要區分，裸名就是對的名字。
   只上 npm 的模組，或把建置產物直接 commit 進 source branch 的模組
   ( fedep 自己就是，`files` 只有建置出來的 `cli.js`，放在 master 上 )，都屬此類

也因此 `fedep publish` 不加 `-g` 時完全不打 tag：npm 發布沒有第二側，
蓋上 `src/` 反而暗示有。

查最後一次 tag 時要指定查哪一側，否則前綴會混進排序：

    git tag --sort=-v:refname -l 'dist/v*' | head -1   # 有 release branch
    git tag --sort=-v:refname -l 'v*' | head -1        # 無 release branch


### 方式 A：手動 git tag

適用於沒有 release branch 的 repo ( 只上 npm，或建置產物直接 commit 進
source branch )，tag 用裸名：

    git add CHANGELOG.md package.json && git commit -m "release vX.Y.Z"
    git push origin master
    git tag vX.Y.Z && git push origin vX.Y.Z

GitHub release 要另外建。與其在網頁 UI 上貼，不如把 CHANGELOG 對應 section
接給 `gh` —— 網頁表單送出的內容會帶 `\r\n` 換行：

    sed -n '/^## vX.Y.Z$/,/^## v[0-9]/p' CHANGELOG.md | sed '1d;$d' \
      | gh release create vX.Y.Z --title X.Y.Z --notes-file -

npm 與 GitHub 兩半要一起做完。只做一半很容易，而且沒有任何提示 ——
fedep 自己就有七個版本上了 npm 卻沒有對應的 tag 與 release。


### 方式 B：fedep publish ( 推薦，可自動建 GitHub release )

前提：

 - `package.json` 的 `version` 欄位需與 CHANGELOG.md 版本一致
 - `gh` CLI 已安裝並登入 ( `gh auth login` )
 - 已 commit 所有變更 ( 包含更新後的 CHANGELOG.md 和 `package.json` )

更新 `package.json` version 欄位後：

    git add CHANGELOG.md package.json && git commit -m "release vX.Y.Z"
    git push   # 先推 master branch，再 publish

    # web 專案 ( 無 dist 資料夾 )
    npx fedep publish -g --skip-dist

    # 有 dist 的 npm 套件
    npx fedep publish -g

fedep 會自動：

 1. 確保 `release` branch 存在 ( 本地 + 遠端 )
 2. 更新 release branch ( `git worktree` + push )
 3. 執行 `gh release create dist/vX.Y.Z --notes-file -`，release notes 從
    CHANGELOG.md 對應版本 section 讀取
 4. 在當前的 source commit 上打 `src/vX.Y.Z` 並 push ( fedep 1.8.0 起 )

只有 `-g` 這條路徑會打 tag。`fedep publish` 走 npm，不打 tag。

詳細 fedep 文件見：[framework/fedep/index.md](framework/fedep/index.md)


## package.json version 欄位

使用 fedep publish 時，`package.json` 的 `version` 必須對應 CHANGELOG.md 的版本。建議每次 release 前同步更新：

    {
      "version": "0.1.0"
    }


## package-lock.json 的版號同步

`package-lock.json` 內有兩處 `version` 欄位 ( 頂層與 `packages[""]` ) 記錄的是
本套件自己的版號。**只手改 `package.json` 時 lock 不會跟著動**，會留在舊版號 ——
下次任何人 `npm i` 就會冒出一個與當次修改無關的 lock diff，混進別的 commit。

因此改版號後請跑一次 `npm i` 讓 lock 同步，並與版號變更收進**同一個 commit**：

    # 手改 package.json version 後
    npm i
    git add package.json package-lock.json

或直接用 `npm version` 指令 ( 會同時改兩個檔案並自動 commit + tag，
不想要自動 commit 可加 `--no-git-tag-version` )：

    npm version patch --no-git-tag-version

註：`npm publish` 本身不受影響 ( lock 不進 tarball )，純粹是保持 repo 乾淨、
避免 lock diff 飄進無關 commit。
