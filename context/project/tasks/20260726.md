# `@plotdb/guides` Context Linking 設計規格

## 1. 目標

`@plotdb/guides` 是集中管理工作摘要、開發規範與共用 context 的 repository／npm package。

每個專案透過：

```bash
npx @plotdb/guides init
```

將 guides 內容連結至：

```text
context/shared
```

設計需同時支援：

1. **Local 模式**

   * 每個 repo 安裝自己的 `@plotdb/guides`
   * 可透過 `package.json` 與 lockfile 固定版本
   * 適合團隊協作與 CI

2. **Global 模式**

   * 多個 repo 共用 globally installed `@plotdb/guides`
   * 更新一次即可影響所有已連結的 repo
   * 適合個人管理大量專案

3. Repo 內保留簡短且 generic 的 context 線索，讓人與 LLM 知道如何使用共用 context。

4. 不將使用者電腦上的絕對路徑提交進 Git。

---

## 2. Repo 結構

初始化後，專案結構如下：

```text
context/
  index.json
  shared -> <@plotdb/guides package>/src
```

其中：

* `context/index.json` 提交進 Git
* `context/shared` 是本機 symlink
* `context/shared` 不提交進 Git
* symlink 由 `@plotdb/guides init` 建立或修復

`.gitignore` 應包含：

```gitignore
/context/shared
```

CLI 應自動加入此規則，且避免重複加入。

---

## 3. `context/index.json`

`context/index.json` 主要給人與 LLM 閱讀。

第一版不建立正式的 context package schema，也不要求 agent 預先安裝 resolver。

建議預設內容：

```json
{
  "system": "check path 'context/shared' for context info (from github:plotdb/guides)"
}
```

設計原則：

* `system` 是自然語言 system prompt
* LLM 不需要理解額外欄位規格
* `context/shared` 是 agent 實際應讀取的本機路徑
* `github:plotdb/guides` 用來留下來源線索
* 未來需要時仍可加入其他欄位
* 第一版暫不使用 `package` 欄位

執行 `init` 時：

* 若 `context/index.json` 不存在，建立預設檔案
* 若檔案已存在，不得覆寫或修改

---

## 4. npm package 與 CLI

npm package 名稱：

```text
@plotdb/guides
```

不另外建立 `plotdb-guides` package。

主要執行方式：

```bash
npx @plotdb/guides init
npx @plotdb/guides init -g
```

`package.json` 需要提供一個 CLI bin，例如：

```json
{
  "name": "@plotdb/guides",
  "bin": {
    "guides": "./bin/guides.js"
  }
}
```

或：

```json
{
  "name": "@plotdb/guides",
  "bin": {
    "plotdb-guides": "./bin/guides.js"
  }
}
```

由於 package 只有一個 bin，以下指令應可直接執行該 CLI：

```bash
npx @plotdb/guides init
```

本設計的正式文件與操作說明一律使用：

```bash
npx @plotdb/guides
```

不依賴或保留：

```bash
npx plotdb-guides
```

## 5. Local 模式

### 指令

```bash
npx @plotdb/guides init
```

### 安裝

從 GitHub 安裝：

```bash
npm install -D github:plotdb/guides
```

正式發布 npm package 後：

```bash
npm install -D @plotdb/guides
```

### Context 來源

```text
<project>/node_modules/@plotdb/guides/src
```

### 建立結果

```text
context/shared -> ../node_modules/@plotdb/guides/src
```

實際 symlink 應依目錄深度計算正確的相對路徑。

### 特性

* 版本記錄於 `package.json`
* lockfile 可固定實際版本
* 不同 repo 可使用不同 guides 版本
* 適合多人協作、CI 與正式專案
* 每個 repo 需各自安裝與更新

---

## 6. Global 模式

### 安裝

從 GitHub globally 安裝：

```bash
npm install -g github:plotdb/guides
```

正式發布後：

```bash
npm install -g @plotdb/guides
```

### 初始化

```bash
npx @plotdb/guides init -g
```

或：

```bash
npx @plotdb/guides init --global
```

### `-g` 的意義

`-g` 表示：

> 將 `context/shared` 連結至 globally installed `@plotdb/guides`。

它不是指 CLI 本身必須從 global package 執行。

例如，CLI 可能由 npx cache 執行，但 context source 來自 global npm root。

### Global package 路徑

CLI 不應自行猜測：

```text
/usr/local/lib/node_modules
/opt/homebrew/lib/node_modules
~/.nvm/...
```

必須透過：

```bash
npm root -g
```

取得目前 npm 環境真正的 global package root。

Context 來源為：

```text
$(npm root -g)/@plotdb/guides/src
```

### 建立結果

```text
context/shared -> <global npm root>/@plotdb/guides/src
```

### 特性

* 多個 repo 共用同一份 guides
* 更新 global package 一次即可
* 已存在的 symlink 不需重新建立
* 適合個人管理大量 repo
* 不保證其他協作者已安裝相同 global package
* 不應被視為可重現的專案 dependency

---

## 7. 更新方式

### Local 模式

正式 npm package：

```bash
npm update @plotdb/guides
```

GitHub dependency 可重新安裝：

```bash
npm install -D github:plotdb/guides
```

每個 repo 需分別更新。

### Global 模式

正式 npm package：

```bash
npm update -g @plotdb/guides
```

GitHub dependency：

```bash
npm install -g github:plotdb/guides
```

因為各 repo 的 `context/shared` 都指向同一份 global package，更新後會直接看到新內容，不需逐一重新執行 `init`。

---

## 8. `init` 指令行為

### Local init

```bash
npx @plotdb/guides init
```

只尋找：

```text
<project>/node_modules/@plotdb/guides/src
```

若不存在，顯示：

```text
Local @plotdb/guides was not found.

Install it locally:
  npm install -D github:plotdb/guides

Or use the globally installed package:
  npx @plotdb/guides init -g
```

Local 模式找不到 package 時，不應自動 fallback 至 global。

這可避免專案在不明顯的情況下依賴使用者個人環境。

### Global init

```bash
npx @plotdb/guides init -g
```

處理流程：

1. 執行 `npm root -g`
2. 取得 global npm root
3. 組成 `@plotdb/guides/src` 路徑
4. 確認該目錄存在
5. 建立 `context/shared` symlink

若不存在，顯示：

```text
Global @plotdb/guides was not found.

Install it with:
  npm install -g github:plotdb/guides
```

---

## 9. `init` 完整流程

執行 local 或 global init 時：

1. 找到目前專案 root
2. 判斷使用 local 或 global mode
3. 解析 `@plotdb/guides/src` 的實際來源
4. 確認來源目錄存在
5. 建立 `context/` 目錄
6. 檢查 `context/shared`
7. 建立或修復 symlink
8. 更新 `.gitignore`
9. 視需要建立 `context/index.json`
10. 顯示初始化結果

### `context/shared` 已存在時

#### 正確 symlink

若已指向預期來源：

* 不重新建立
* 回報已正確設定

#### 錯誤或失效 symlink

若是 symlink，但來源錯誤或已失效：

* 移除舊 symlink
* 建立新 symlink

#### 一般檔案或實體目錄

若 `context/shared` 是一般檔案或目錄：

* 不得自動刪除
* 不得覆寫
* 顯示錯誤並中止

例如：

```text
context/shared already exists and is not a symbolic link.

Move or remove it manually before running init again.
```

---

## 10. `.gitignore` 更新

CLI 應確保專案根目錄的 `.gitignore` 含有：

```gitignore
/context/shared
```

規則：

* `.gitignore` 不存在時可以建立
* 已有相同規則時不重複加入
* 加入時應維持原檔案內容
* 使用根目錄限定的 `/context/shared`
* 不使用過度廣泛的 `context/shared` 或 `shared`

可視需要在前方加入註解：

```gitignore
# Local shared agent context
/context/shared
```

但第一版也可只加入單行規則。

---

## 11. Symlink 原則

`context/shared` 必須被視為本機 materialized state，而不是 repository source。

它不可 commit，因為實際路徑可能受以下因素影響：

* npm prefix
* Node.js 版本
* nvm、fnm 或 Volta
* Homebrew
* 作業系統
* 使用者 home directory
* local 或 global 安裝方式

Repo 真正需要提交的是：

```text
context/index.json
.gitignore
package.json       # 僅 local 模式需要 dependency
package-lock.json  # 僅 local 模式需要鎖定版本
```

每台機器可透過 `init` 重建 `context/shared`。

## 14. 可延後功能

第一版只需要實作 `init`。

未來可考慮：

### Status

```bash
npx @plotdb/guides status
```

顯示：

```text
Mode: global
Source: /opt/homebrew/lib/node_modules/@plotdb/guides/src
Link: context/shared
Link status: valid
Context index: present
Git ignore: configured
```

### Unlink

```bash
npx @plotdb/guides unlink
```

只移除：

```text
context/shared
```

保留：

```text
context/index.json
context/
```

### Doctor

```bash
npx @plotdb/guides doctor
```

檢查：

* `context/index.json` 是否存在
* `context/shared` 是否存在
* symlink 是否失效
* symlink 是否指向正確來源
* local/global package 是否存在
* `.gitignore` 是否正確

## 15. 第一版實作範圍

必須支援：

```bash
npx @plotdb/guides init
npx @plotdb/guides init -g
npx @plotdb/guides init --global
```

第一版功能：

* 解析 local package 路徑
* 使用 `npm root -g` 解析 global package 路徑
* 建立 `context/`
* 建立或修復 `context/shared`
* 自動更新 `.gitignore`
* 建立最小 `context/index.json`
* 不覆寫現有實體檔案或目錄
* 提供清楚的錯誤與成功訊息
* 支援 macOS 與 Linux

第一版不需要：

* `plotdb-guides` package
* `npx plotdb-guides` 命令
* 自訂 global cache
* Git worktree
* 多版本 global checkout
* 正式 context package schema
* `package` 欄位
* 自動更新 guides
* local 自動 fallback global
* provider-specific adapter
* Windows symlink 相容處理
* status、doctor、unlink 等額外指令

## 16. 使用情境

### 個人管理多個 repo

安裝一次：

```bash
npm install -g github:plotdb/guides
```

每個 repo 執行：

```bash
npx @plotdb/guides init -g
```

更新：

```bash
npm install -g github:plotdb/guides
```

所有 global symlink 會直接取得新版內容。

### 多人協作與版本固定

每個 repo 安裝：

```bash
npm install -D github:plotdb/guides
```

初始化：

```bash
npx @plotdb/guides init
```

提交：

```text
package.json
package-lock.json
context/index.json
.gitignore
```

不提交：

```text
context/shared
```

## 17. 最終設計結論

Repo 內以 generic 的 `context` 目錄作為 agent context 入口：

```text
context/
  index.json
  shared -> @plotdb/guides/src
```

`context/index.json`：

```json
{
  "system": "Use context/shared (github:plotdb/guides)"
}
```

CLI 與 package 統一使用：

```text
@plotdb/guides
```

正式操作方式：

```bash
npx @plotdb/guides init
npx @plotdb/guides init -g
```

來源規則：

```text
init
  → <project>/node_modules/@plotdb/guides/src

init -g
  → $(npm root -g)/@plotdb/guides/src
```

Local 模式提供版本可重現性與團隊協作；Global 模式提供多 repo 集中管理與一次更新。兩種模式明確分開，不自動 fallback。

這份可直接交給開發 agent 實作。
